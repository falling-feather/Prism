# 通用编辑与来源适配 · v0.4

目标是让不同技术形式共享编辑、剪辑、保存和导出能力。适配器按技术形式建立，不以某部作品、人物名称或绘制函数名作为核心逻辑分支。《一秒钟》等已有作品用于考察真实需求；本轮没有改写这些作品的源码。

## 已实现的边界

本轮交付 SVG 与 Canvas 2D 程序动画的混合编辑。保留既有 SVG、关键帧与细胞工程；增加 `canvas-program-v1`。统一复用对象选择、父子关系、变换覆盖、文字、参数、撤销、镜头与音轨。Canvas 保留原生绘制，预览不将程序转换为 SVG；当前帧 SVG 中的 Canvas 画面以位图保存，工程文件仍保留可编辑程序与对象声明。

HTML DOM、原生WebGL三维网格和视频片段尚未提供内置适配器。0.4.2试用版支持Canvas 2D纹理经WebGL后期合成的来源，保留原始着色器。任意网页程序与 MP4 不会自动还原为对象工程。旧 Canvas 程序需要在来源侧提供声明与渲染入口；符合接口的新工程不需要修改映物核心。

v0.4.1已增加[原始源码目录读取](07-原始源码目录读取.md)：编辑器可直接分析符合渲染入口约定的Canvas源工程，自动建立对象声明。用户不需要先手工改写为规范格式；复杂DOM／三维程序仍在当前支持范围之外。

## 编辑与时序

- 来源内容不可变，文字、布局和参数修改属于剪辑。复制或拆分镜头保留独立编辑；撤销共享来源与素材，不复制大型媒体。
- 参数由来源声明类型、默认值与范围；编辑器据此提供控件。来源程序通过稳定 ID 读取参数，不依赖工作台的面板实现。
- Canvas 来源报告逻辑坐标中的对象边界与运动矩阵，选择框沿用相同变换。父对象的变换同时作用于后代；文字边界由实际排版计算。
- 连续拖动只保留一个正在绘制的请求和一个最新候选，最终呈现最新时间；连续播放按完成顺序显示中间帧，避免较慢绘制导致画面停住。导出逐帧等待对应结果。切镜与重新导入释放旧 Worker、位图和请求。
- Canvas 按预览或导出分辨率绘制，编辑坐标保持逻辑画幅。图片按实际使用加载，单帧解码预算有限，超限报错。
- 声音沿用现有全片时间语义。追加工程会整体平移新增音轨；普通镜头裁剪、排序仍不隐式移动既有音轨。

## 程序与素材边界

来源程序运行于不透明来源 iframe 内的 Worker，无法访问编辑器的 DOM 与 IndexedDB；CSP 禁止直接联网。素材由宿主按来源声明的别名提供。每次初始化和绘制均有超时，失败会给出来源或对象信息，首次载入失败恢复原工程。

媒体使用内容哈希标识。自包含小工程继续使用 JSON；独立媒体以 `.prism` 工程包交付，包中保存相对资源路径。导入不解压任意文件路径；本机服务只按登记编号提供素材，音频支持 Range 请求。单文件 HTML 仍有容量上限，大工程使用工程包或 MP4。

Worker 与 ImageBitmap 的实现依据见 [Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers) 和 [ImageBitmap 生命周期](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas/transferToImageBitmap)。实际能力以本机回归为准。

## 后续适配器的接入要求

新技术形式应提供来源校验、对象清单、按来源时间渲染、对象几何、快照输出及资源释放；异步实现返回就绪 Promise。类型在来源与绘制注册处安装，时间轴、编辑历史和工作台不添加作品专用分支。

新增能力以独立样例验证，不把某部影片作为唯一验收依据。现有两个 Canvas 样例分别使用函数组合与类实现，另有包含 SVG 的混合工程。测试范围与尚未覆盖项统一见 [验证记录](VALIDATION.md)。
